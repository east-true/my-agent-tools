# github issue create

기존 읽기 전용 생성 계획(`--dry-run`)과 실제 실험 이슈·연결 브랜치 생성·로컬 체크아웃을 각각 측정했습니다. 서로 다른 실행 조건이므로 옵션 하나의 효과로 비교하지 않습니다. 기존 이슈의 브랜치 생성·재개는 [issue-branch](issue-branch.md)에 있습니다.

## 실제 실험 이슈·브랜치 생성

`tools github issue create --prefix fix --title "measure command workflow" --body-file body.md --json`과 직접 `gh api + git`를 비교합니다. 한국어 본문, 영어 `fix:` 제목, 인증 사용자, 기존 `bug` 라벨·`Bug` 유형으로 이슈 1개를 생성하고 번호 기반 브랜치를 Development에 연결한 뒤 fetch·로컬 체크아웃합니다.

2026-10-07, `gpt-6.1-sol`, high 추론, 방식별 새 세션 3회입니다. 실제 `gh`·Git·프로덕션 CLI와 로컬 실험 API를 사용했습니다. 토큰은 캐시 입력을 포함한 에이전트 작업 전체의 값입니다.

| 평균 또는 범위 | 직접 `gh + git` | `tools` |
|---|---:|---:|
| 총 토큰 | 116,141 | 34,768 |
| 캐시 제외 입력 | 19,685 | 20,176 |
| 캐시 입력 | 95,403 | 14,464 |
| 출력 토큰 | 1,053 | 128 |
| 쉘 명령 항목 | 11.67 | 2 |
| 실행 시간(초) | 45.52 | 12.95 |
| 총 토큰 범위 | 97,876–151,713 | 29,808–44,677 |

총 토큰 차이는 −70.1%, 캐시 제외 입력은 2.5% 많았습니다. 비교한 6회 모두 반환 JSON과 독립적인 최종 상태 검증을 통과했습니다. 이슈 전체 메타데이터, 연결 생성 1회, 원격·로컬·추적 참조의 SHA, HEAD·upstream과 작성 파일 보존을 확인했습니다. GitHub 서비스에 게시하지 않고 로컬 실험 서버와 실제 임시 Git 저장소를 변경했습니다.

최초 직접 처리 3회는 원본에 보존하고, `python3` 안내를 명확히 한 3회와 기존 `tools` 결과를 비교했습니다. 템플릿·충돌·부분 실패 복구는 포함하지 않습니다.

[공통 조건·제외 기록·재현](command-suite.md), [공유 원본](commands.json)의 `issue-create` 항목을 확인하세요. 캐시는 통제하지 않았으며 금액 절감을 입증하지 않습니다.

## 사용 안내 포함 측정

2026-10-07에 `gpt-6.1-sol`, high 추론, 방식별 새 세션 3회로 동일한 계획을 비교했습니다. 양쪽에 사용 안내를 제공했고, 직접 `gh` 처리도 명령 묶음과 로컬 필터를 사용할 수 있었습니다.

| 평균 | 직접 `gh` | `tools` |
|---|---:|---:|
| 총 토큰 | 46,630 | 46,279 |
| 캐시 제외 입력 토큰 | 16,035 | 16,063 |
| 쉘 호출 | 2 | 2 |

총 토큰 차이는 −0.75%이며, 캐시 제외 입력은 사실상 같습니다. 이슈 생성의 의미 있는 절감은 입증하지 못했습니다. 비교한 계획 6개는 모두 기준과 일치했습니다.

프롬프트·조건·개별 실행·검증 결과는 [원본 JSON](issue-create.json)에 있습니다.

## 사용 안내 없는 초기 측정

초기 실험에서는 탐색과 wrapper 검사 비용도 포함했습니다. 평균 총 토큰은 직접 `gh` 81,348, `tools` 146,013으로 절감이 없었습니다. 생성 계획 6개는 모두 일치했습니다.

후속 실험은 안내·로컬 Git 메타데이터 등 여러 조건을 함께 변경했으므로 두 결과의 차이를 도움말 변경 하나의 효과로 해석하지 않습니다. 세부 조건과 한계는 [초기 원본 JSON](issue-create-unguided.json)에 있습니다.
