# 파일시스템 명령

`tools fs`는 Git·GitHub 인증 없이 파일 탐색·증분 조회·배치 수정을 처리합니다.

| 명령 | 동작 |
|---|---|
| [inspect](inspect.md) | 파일별 구간·패턴·명시한 raw 파일의 전체 원문, Markdown 목차·섹션, 커서로 이어 읽기 |
| [delta](delta.md) | 해시 스냅샷·변경 구간·기준 보존, 실제 반복 관찰의 중복 보고 제거 |
| [apply](apply.md) | 해시 계획 생성·정확한 오류 진단·전체 검증·반영·실제 파일 재검증 |
| [test-results](test-results.md) | JUnit suite 합계·실패 원문·누락 판독, 실행 완료와 구분 |

경로는 `--root` 기준 `/` 구분 상대 경로입니다. `..`·절대 경로·심볼릭 링크는 파일 대상으로 허용하지 않습니다. 읽기 선택의 기본 제외 디렉터리는 `.git`, `.tools`, `.codex`, `.claude`, `.agents`, `.aws`, `node_modules`, `dist`, `artifacts`, `__pycache__`입니다. `.gitignore`는 해석하지 않으므로 추가 제외는 `--exclude`로 명시합니다.

`--include`, `--exclude`, `--path`, `--pattern`은 반복 가능합니다. glob은 `*`, `?`, `[]`, 디렉터리 전체를 뜻하는 `**`를 지원합니다. `/` 없는 glob은 파일·디렉터리 이름에 적용합니다. 결과는 정렬된 JSON이며 `--json`을 명시해도 같은 형식입니다.

조회 기본 상한은 선택 파일 200개·파일당 1 MiB·결과 64 KiB입니다. `--max-files`, `--max-file-bytes`, `--max-output-bytes`로 조정합니다. inspect의 출력이 한 페이지를 넘으면 `status: page`, `complete: false`, `next_cursor`와 종료 코드 0을 반환합니다. 같은 요청과 커서로 끝까지 이어 읽습니다. 파일 선택·권한·읽기 오류는 `partial`과 종료 코드 1입니다. 성공은 0, 인자 파싱 오류는 2입니다.

SHA-256은 줄바꿈을 정규화하기 전 실제 바이트로 계산합니다. 텍스트 조회는 UTF-8과 CRLF를 지원하고 출력 줄 번호는 1부터 시작합니다. 바이너리는 메타데이터 조회와 해시 비교가 가능하며 텍스트 수정은 지원하지 않습니다. 실행 중 컨텍스트 취소와 읽기 중 관찰된 파일 변경을 처리합니다.

단순 검색·복사·이동은 직접 명령으로도 짧게 처리할 수 있습니다. 실제 에이전트 토큰 비교는 [파일시스템 벤치마크](../benchmarks/fs/README.md)에 기록합니다.

조회·계획·반영·재검증을 함께 수행하는 [에이전트 사용 방법](agent-usage.md)을 제공합니다. 효율과 토큰 중 하나만 개선한 결과는 부분 개선으로 기록하고 두 조건의 동시 달성을 목표로 합니다.

[큰 보고서 복구](reports.md)는 결과 상한을 넘은 진단·변경 구간을 저장하고 필요한 원문만 읽는다. delta 기준 갱신과 apply 재실행을 하지 않으며 저장 당시의 상태와 현재 파일 검증을 구분한다.
